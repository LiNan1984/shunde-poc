## Q2. 是不是数据埋点缺少？

### 明确结论：**主要不是。Verdict：主要不是（埋点只是运营助手中的一块）。**

「数据埋点」在 POC 语境里，主要对应 **运营助手 → HOOK 开发能力**（会话/渠道活跃、token/模型/失败率、用户反馈/转化、工具调用/耗时/人工确认）。这部分确实还没做，但它只是六大考察大类之一，且运营助手本身还有 MCP、SKILL、业务理解方案要交。

### 至少两类「非埋点」硬缺口（证明不只是埋点）

1. **Excel MCP 三类异常能力未做**：文件损坏检测、编码自动识别、超大文件分块 —— 属于 MCP 开发验收，不是埋点。  
2. **多模态知识库软件栈未建**：ElasticSearch + MySQL + GALASYBASE + MinerU/Embedding/Reranker 建库检索 —— 属于知识库工程，不是埋点。  
3. **（补充）后端 `/health` 与镜像体积、模型清单 Qwen3.6 vs 当前探针 `qwen3.5-35b-a3b` 不一致** —— 同属非埋点缺口。

若把「埋点」理解为运营 HOOK/指标采集：它约占整体 POC 演示工作量的 **约 10%～15%**，不是主因。

## Q4. 开发周期多久？

### 假设

- **人力**：2 人全职（1 偏 Agent/Skill/MCP，1 偏知识库/中间件/部署）。  
- **前置**：行方按时提供 Qwen3.6-*、Embedding、Reranker、MinerU、ES/MySQL/GALASYBASE（或等价联调环境）；GALASYBASE 接口文档可用。  
- **目标**：演示日可打分的「demo-ready」，不是生产级高可用。

### 分项人天（人·日）

| 工作包 | 人·日（区间） | 说明 |
|--------|---------------|------|
| 模型/密钥接入与合规对齐（含 Qwen3.6 确认） | 1～2 | 自定义 Provider + 环境变量 |
| EXCEL 助手（Skill + 异常 MCP + 12 题回归） | 4～6 | |
| 报告可视化助手（docx+表+五类图） | 4～6 | 可与 Excel 部分复用 |
| 运营助手（MCP+Skill+HOOK 埋点四类） | 5～7 | **含埋点** |
| 后端镜像精简 + `/health` + 资源截图 | 3～5 | Chromium 裁剪风险较高 |
| 多模态知识库（解析+三库+检索+4 题+接入） | 12～18 | **最大块**；GALASYBASE 未知则取上沿 |
| HARNESS 三方案讲义与调参演示 | 2～3 | 以阐述为主 |
| 联调、演示彩排、答卷/截图整理 | 3～5 | |
| **合计** | **约 34～52 人·日** | |

### 日历工期（2 人并行）

| 排期方式 | 日历时间 |
|----------|----------|
| 知识库与助手并行（推荐） | **约 3.5～5.5 周** |
| 单人串行 | **约 7～10 周** |
| 若 GALASYBASE/模型环境延期 | 每延期 1 周，整体顺延 1 周（知识库关键路径） |

**埋点单独工期**：约 **2～3 人·日**（HOOK/Middleware + 四类指标演示），不能替代上表其他工作包。

## Q5. 验收标准有哪些？

以下对齐 POC 选型方案中的考察点与软件要求，可作为演示/打分清单。

### A. 软件与环境

1. QwenPaw 版本为 **v2.0.0**。  
2. 向量库使用 **ElasticSearch**，关系库 **MySQL**，图库 **GALASYBASE**（或评委认可的等价证明与接入说明）。  
3. 演示模型清单可核验：**Qwen3.6-35B、Qwen3.6-27B、MinerU2.5-Pro-2604-1.2B、Qwen3-Reranker-0.6B、Qwen3-Embedding-8B**（不得仅用未在清单中的模型冒充合规而不说明差异）。  
4. 开发过程符合行方约束：**VS Code + Cline + Qwen3.6-27B** vibe-coding 环境可举证。  
5. 除模型外，自研服务支持内网部署。

### B. EXCEL 文件问答助手

6. **12 道**测题（读/查/析/写）回答准确，可展示预跑结果。  
7. MCP 现场处理 **三种异常 Excel**（损坏、编码、超大分块）并返回正确提示。  
8. 提交 SKILL 文档：名称/描述/触发词/参数/返回值/边界清晰。

### C. 多模态文件问答助手

9. 讲解并截图证明：原生文本、OCR、表格多格式、图片短描述、切块。  
10. 建库三件套可指认：对象存储页图、关系库元数据、向量库块向量（及图库若要求）。  
11. 检索策略可阐述：BM25、文本向量、图像向量、过滤条件。  
12. **缺块漏块 4 题**回答准确。

### D. 运营助手（含埋点）

13. 运营数据问答/分析测题可演示。  
14. 业务理解方案说清「如何把智能体使用情况反馈运营方与开发者」。  
15. HOOK 四类指标获取方案可讲清并可演示数据来源：  
    - 会话/渠道/用户活跃  
    - token/模型/失败率  
    - 用户反馈/转化  
    - 工具调用/耗时/人工确认  

### E. 报告可视化助手

16. 输入纯文字（含数据）生成 **docx**，内容无缺失。  
17. 排版：标题层级、段落结构、间距、字体字号、页眉页脚合格。  
18. 支持动态多维交叉表；支持柱/折/饼/面积/散点等图表。

### F. 后端部署

19. Dockerfile 多阶段/层优化可展示；镜像体积 **低于 500MB**；构建 **低于 5min**（截图）。  
20. 启动 **低于 30s**；存在 **`/health`** 健康检查端点（截图）。  
21. 运行资源：CPU **低于 2 核**、内存 **低于 2GB**（截图）。

### G. HARNESS

22. **上下文压缩**方案：算法（摘要/检索/遗忘）、频率、保留率、耗时影响 —— 阐述可行。  
23. **长期记忆**方案：数据结构、存储、召回准确率与速度、增删改过期策略 —— 阐述可行。  
24. **工具沙箱**方案：进程/网络/文件系统隔离、CPU/内存/磁盘/网络限制、操作日志与权限 —— 阐述可行。

## Q6. 一句话给管理层

**距离 POC 演示验收还差一整轮「六大场景开发 + 知识库中间件 + 部署达标」；缺口主因不是数据埋点，埋点只是运营助手里约一两成工作。按 2 人全力投入，正常约 3.5～5.5 周可到 demo-ready（合计约 34～52 人·日），最大风险在多模态知识库与行方模型/GALASYBASE 环境是否按时就绪。**
